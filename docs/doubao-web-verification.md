## 维护者实测反馈与首次启动修复

2026-10-27，维护者报告“测试没问题，翻译正常”，同时报告首次启动时翻译失败，需手动进入设置点击检查才能恢复。维护者没有提供浏览器及版本、首次错误码、目标语言或完整场景清单，因此该反馈只记为用户报告的普通翻译成功，不用于宣告 Chrome / Edge 的全部平台矩阵通过。

代码审查确认，旧实现遇到鉴权或服务拒绝后会保留阻断状态，只有设置中的主动检测能解除；普通翻译成功也没有更新连接状态。首次请求本身为什么失败尚未由错误码或请求记录确认，不能直接归因于 Cookie、网络或特定浏览器。

本次修复让新发起的翻译也能共享新的会话准备，不要求到设置解锁；初次 launch 的网络瞬断 / 5xx 可使用一次有限重试，与后续文章请求及缺项补发共享预算。真实完整翻译成功才更新可用状态；缓存、纯本地返回或 launch 成功均不算登录验证。旧失败任务不自动重放，鉴权、服务拒绝和限流仍按错误处理，429 冷却继续生效。

### 打包后的最短测试路线

1. 将 Chrome / Edge 测试 ZIP 解压，在扩展管理页加载其中含 `manifest.json` 的目录。
2. 确认旧服务、原有密钥与启停状态保留。打开设置，选择豆包。
3. 点击“打开豆包并登录”，在同一浏览器资料目录登录自己的账号。关闭并重启浏览器，不先进入设置检测，直接在普通公开网页翻译两段短文；再重载扩展复测首次翻译。
4. 检查段落顺序和原文恢复；再检查行内链接、代码、长段和动态内容。“重新检测”作为可选诊断另行测试，不用它预热首次启动场景。
5. 在已有文本层 PDF 和已安装本地 OCR 的图片上测试；核对公式、目录页码、图片文字位置。
6. 退出豆包，确认明确失败且没有持续重发；重新登录后直接重试翻译，确认无需先检测即可恢复。限流时遵守界面等待时间，不反复触发请求。
7. 记录浏览器版本、扩展版本、时间、是否同一资料目录、目标语言、脱敏错误及最小复现。不要提交 Cookie、密码、API Key、账号标识或包含凭据的 HAR。

测试包用于验证这次实验实现，不表示正式发布或承诺豆包网页接口可持续使用。
