# WuPage 豆包网页登录翻译需求

## 1. 目标与当前状态

让不熟悉 API Key 的用户，在同一浏览器登录豆包后，即可用 WuPage 翻译网页、段落、文本层 PDF 和本地 OCR 识别出的文字。

新增服务名称为 **豆包（网页登录，实验）**，类型为 `doubao-web`；首版仅使用文章翻译接口及 `translate_service: "1"`。接入机制见 [spec.md](spec.md) 第 2 节。

目前已完成静态协议还原与仓库分析，尚未验证线上可用性。Chrome、Edge 必须分别通过 P0 真实会话验证，才能推进上线；Firefox 独立验收。复现步骤与证据范围见 spec 第 3、8 节。

## 本次实现的执行顺序

2026-10-27，仓库维护者要求先按本设计完成实验实现、提交到自己 fork 的 `main` 进行评审和 CI，再打包验证真实账号效果。因此 P1/P2 和可脱离账号的自动测试先执行；P0 真实会话、Origin 对照、平台和效果验收保留为后续测试项，不能标记为已通过。当前按参考扩展的固定 Origin 兼容模式实现，尚未证明这是线上必要或有效的模式。Firefox 豆包入口暂不可用。完整证据与人工测试表见 [验证记录](../doubao-web-verification.md)。

## 2. 功能范围

| 项目 | 本期要求 |
| --- | --- |
| 服务入口 | 在现有设置、弹窗、悬浮球和 PDF 服务选择器中增加可选内置服务；保留用户当前服务。 |
| 登录方式 | 用户在同一浏览器资料目录的豆包官网自行登录，扩展复用浏览器可用的登录态。 |
| 配置界面 | 提供说明、打开豆包、重新检测和状态；不要求填写 API Key、Cookie、模型、提示词或接口地址。 |
| 原文入口 | 复用网页全文、段落、文本层 PDF 与本地 OCR 文字，不新增字幕、聊天框自动化或图片上传。 |
| 源语言 | 豆包自动识别；界面说明有效行为，保留用户为其他服务设置的源语言。 |
| 目标语言 | 逐项验证现有 `zh-CN/en/ja/ko/fr/de/es/ru`；未证实支持的项目不能选择，不静默换语种。 |
| 显示与格式 | 保留当前原文恢复、段落对应、三种显示模式、代码/公式保护和布局能力。 |

“无损接入”指不降低 WuPage 已有保护能力，不承诺任意 HTML 标签完整往返、所有版式不变或译文语义绝对无损。入口与边界见 spec 第 4、5.5 节。

## 3. 用户流程

1. 在翻译服务中选择“豆包（网页登录，实验）”；仅选择服务不会自动打开网站或发送页面正文。
2. 点击“打开豆包”，在官网正常登录；不在扩展中输入账号密码。
3. 回到设置页点击“重新检测”。扩展发送固定的无敏感内容短文，不使用当前网页内容或已有翻译缓存。
4. 检测翻译成功后显示“可以翻译”及最近检测时间，再按原有方式翻译内容。
5. 登录失效或请求受限时，保留原文及已完成译文；按提示处理后，由用户主动重新检测或重试。

检测结果只代表最近一次请求。初始化接口 `launch` 成功、缓存命中或曾经登录，都不能直接显示为当前可用。

## 4. 状态与恢复

| 用户看到的状态 | 操作 |
| --- | --- |
| 尚未检测 / 检测中 | 允许开始检测；检测中合并重复点击。 |
| 可以翻译 | 显示最近检测时间；实际翻译仍检查错误。 |
| 需要登录 | 打开豆包登录，然后重新检测。 |
| 请求受限 / 服务拒绝 | 显示原因与适用的等待时间；处理后手动重试，不把所有拒绝都称为登录过期。 |
| 权限不足 / 网络异常 | 提示检查扩展站点访问权限或网络，再主动重试。 |
| 接口变化 / 当前浏览器不支持 | 明确说明豆包暂不可用；由用户自行选择其他服务。 |

具体错误分类见 spec 第 5.4 节。切换服务后忽略旧检测结果；失败时不自动把正文转发给其他服务。

登录失败、服务拒绝或限流会释放已排队的普通任务，恢复后不自动重放。主动检测可解除登录/拒绝阻塞，但仍遵守共享串行、请求间隔和限流等待。

“停止翻译”沿用恢复原文、停止前台继续提交和忽略迟到结果的行为；已提交后台的任务在完整时限内收尾，不承诺立即取消所有网络请求。本期不增加端到端取消协议。

## 5. 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| AC-01 | 无密钥启用与旧设置保留 | 新旧用户均能看到豆包选项；无密钥等表单；旧服务选择、自定义服务、密钥及启停状态保留，新配置反复保存不丢失。 |
| AC-02 | 真实检测与登录恢复 | 同一资料目录登录后，固定短文真实翻译成功才显示可用；退出后能提示并停止普通队列；重新登录、主动检测后可恢复，不依赖缓存或 launch 判定。 |
| AC-03 | 语言边界 | 豆包有效源语言为自动识别，切换回其他服务仍保留原设置；8 种目标语逐项有验证结论，未支持项被阻止，界面与后台一致。 |
| AC-04 | 原生批量与结果完整性 | 多段和重复原文均一一对应；乱序响应正确回填；长段不截断；缺项、冲突索引、空结果或异常断流不产生成功缓存。 |
| AC-05 | 网页原文与显示模式 | 全文、段落和动态内容均可翻译；双语、双色及替换模式保持现有表现，切模式不重复请求；恢复后原文正确，迟到结果不覆盖新状态。 |
| AC-06 | 代码与公式保护 | 代码只翻识别出的注释，保留程序文本与行号；行内代码和 PDF 公式的保护标记正确恢复；修复失败保留原文，不缓存损坏结果。 |
| AC-07 | PDF 与 OCR 复用 | 文本层 PDF 的块顺序、公式图像、目录点线及页码沿用现有布局；图片只发送本地识别文字，保留区域坐标、覆盖层和原图切换。 |
| AC-08 | 队列、故障与停止收敛 | 检测、测试服务和所有翻译入口共用单并发及等待规则；受限后无自动重试风暴；每次后台任务含排队、初始化、分片和修复在 110 秒内结束，停止后不出现迟到渲染。 |
| AC-09 | 浏览器能力与服务回归 | Chrome、Edge 分别通过登录/退出、扩展重载、后台休眠和 Cookie 设置验证；Firefox 未通过时仅禁用豆包；现有服务及普通豆包网页行为不受影响。 |
| AC-10 | 来源署名与交付证据 | README 致谢、适配器文件头、实现说明和 PR 描述均保留 Haleclipse 与两条来源链接；各验收项附证据，未完成事项保持待办或阻塞状态。 |

解析、缓存、权限及故障测试方法以 spec 第 5、6 节为准；本需求文档的完成不代表这些验收已经通过。

## 6. 阶段交付

| 阶段 | 交付 |
| --- | --- |
| P0 协议验证 | 当前接口、登录态、Origin 模式、目标语言及浏览器矩阵；关键验证失败则记录阻塞，不发布豆包功能。 |
| P1 适配器 | 初始化、文章 SSE、索引对应、共享队列和有限超时。 |
| P2 用户接入 | 设置迁移、无密钥表单、检测与恢复、现有入口和缓存对接。 |
| P3 保真回归 | 网页、段落、代码、PDF、OCR 与故障收敛的证据。 |
| P4 发布准备 | Chrome/Edge 联调、Firefox 独立结论、既有服务回归和署名说明。 |

执行依赖与任务状态见 [task.json](task.json)；实验开发按上述维护者要求先行，真实可用性仍需满足对应阶段退出条件。
